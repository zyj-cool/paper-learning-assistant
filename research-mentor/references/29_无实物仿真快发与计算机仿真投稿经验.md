# 无实物仿真快发与《计算机仿真》投稿经验

## 适用场景

本参考用于控制、自动化、电子信息、计算机交叉方向的研究生，在无实物平台、无既有代码、基础较弱但需要尽快形成中文核心或科技核心可投稿稿件时使用。典型请求包括：

- “研二没方向、没实物，想做无人机仿真尽快毕业。”
- “有没有开源代码可以起步？”
- “想投《计算机仿真》，中稿概率大一点。”
- “不要再加算法，冻结数据，整理投稿级图表和 Word。”

本参考不用于承诺录用，不用于包装真实飞行实验，也不用于把二维数值仿真夸大成工程实机验证。

## 一、选题判断：先找能被现实托住的题

弱基础快发路线的关键不是追最热门概念，而是选择“已有开源可复现、理论边界清楚、仿真证据能闭合、目标期刊能接住”的题。

优先选择：

1. 二维或简化动力学模型，而不是一开始做真实飞控、三维六自由度或硬件在环。
2. 成熟算法组合上的工程化改进，而不是从零提出大理论。
3. 能量化比较的通信、安全、误差、求解时间等指标，而不是只展示轨迹图。
4. 目标期刊长期接受的建模仿真、路径规划、避障控制、系统仿真类主题。

可迁移主线示例：

“面向通信资源受限的多无人机编队避障，构建事件触发通信、广播状态预测和中央联合 HOCBF-QP 安全滤波方法，并通过多场景随机仿真评价通信减少、安全裕度与计算代价之间的折中。”

使用该示例时必须替换为用户真实对象、算法、数据和目标期刊；不得把示例数据直接套入新稿。

## 二、推荐工作流：先复现，再创新，再冻结

### 阶段 0：定边界

输出：

- 一句话主线。
- 目标期刊候选和选择理由。
- 不做清单：不做硬件、不写真实通信网络、不写动态障碍、不写三维动力学，除非用户确有材料。
- 可改与不可改清单：算法、参数、随机种子、场景、统计口径、数据冻结时点。

### 阶段 1：开源代码起步

先完整读取 README、配置、主入口和源码目录，不要立即重写项目。判断：

- 许可证、依赖、运行入口是否清楚。
- 是否能复现实例输出。
- 代码对应的模型、状态量、控制量和安全约束是什么。
- 哪些部分可作为 baseline，哪些只是参考，哪些不能直接使用。

交付：

- `README.md`
- `assumptions.md`
- 运行脚本
- 初始复现图和指标
- 开源来源与使用边界说明

### 阶段 2：建立可比基线

至少形成“无安全滤波基线”和“安全滤波方法”的区别。无人机/多智能体避障仿真常见基线包括：

- 周期通信标称控制。
- 固定事件触发标称控制。
- 周期通信安全滤波控制。
- 固定事件触发安全滤波控制。
- 所提自适应事件触发安全滤波控制。

先记录失败，不要遮盖失败。安全违反、QP 不可行、fallback、求解器错误都应显式输出。

### 阶段 3：安全闭合优先于创新包装

在提出自适应触发前，先保证安全滤波本身数学和数值可行：

1. 逐式核对安全函数、导数、约束方向和输入上下限。
2. 用单元测试检查手算场景、有限差分、约束矩阵、机间对称性。
3. 显式记录硬 QP 可行性、软 QP、松弛量和物理安全违反。
4. 如果局部约束不可闭合，优先采用中央联合 QP，尤其在 5 架、10 维控制变量等小规模场景下。
5. 区分“求解时约束冲突”和“离散积分后穿越”，必要时只用内部保护距离消除离散穿越，评价指标仍按原始安全距离计算。

不能靠缩小安全距离、改变统计口径、删除失败样本或调参遮盖问题。

### 阶段 4：通信数据流闭合

事件触发论文最容易被质疑的是“明明减少通信，却让中央控制器偷偷使用真实状态”。必须明确：

- 本地事件检测可以使用本机真实状态。
- 中央名义控制和安全滤波只能使用最近广播状态及预测状态。
- 未广播真实状态不得直接输入中央 QP。
- 记录 AoI、预测误差、广播次数和触发分布。

固定阈值与自适应阈值的差异应写成“风险相关的阈值变化”，不要只写“广播更少”。

### 阶段 5：多场景随机统计

在单场景通过后，再做随机统计。推荐做法：

- 每类场景固定随机种子，方法之间同种子配对。
- 先比较安全成功率、任务成功率，再比较广播次数、RMSE、安全裕度、控制努力和求解时间。
- 使用均值±标准差描述总体，使用配对差和 bootstrap 置信区间描述自适应方法相对固定触发的收益。
- 箱线图反映分布，表格反映均值和成功率，二者不要混写。

不要在统计阶段继续调默认参数。若必须改参数，重新冻结并重跑全部方法。

### 阶段 6：冻结证据并成稿

冻结后只允许做论文表达、图表版式和格式治理，不再改算法和数据。至少保留：

- 原始结果表。
- 汇总表。
- 图件源数据映射。
- 参数表。
- 结论—证据台账。
- 数据冻结说明。
- 投稿前终检。

写作时每个核心结论都要能追到图、表或日志。

## 三、《计算机仿真》类期刊表达口径

标题建议保留“仿真研究”“建模仿真”“路径规划仿真”等信号，不写“最优”“高性能”“鲁棒保证”等未经证明词。

摘要按：

“研究问题 → 方法 → 仿真设计 → 主要定量结果 → 结论边界”

引言按：

“研究背景 → 现有方法 → 通信或工程约束 → 现有不足 → 本文方法 → 贡献”

贡献控制为 3 条左右。对于事件触发 + HOCBF-QP 类稿件，可写成：

1. 构建事件通信下基于广播状态预测的闭合信息流。
2. 将局部安全裕度映射到触发阈值，在低风险阶段减少广播、接近边界时提高更新频率。
3. 采用中央联合安全滤波并用多场景随机试验和同种子配对统计评价通信、安全和计算代价折中。

不要把“3 类场景、50 个随机种子”本身写成创新；它属于验证设计。

## 四、核心结论的稳妥写法

当自适应触发不是广播次数最低，但安全裕度更稳时，应主动写成折中：

“自适应事件触发并未取得最低广播次数。相较固定事件触发方法，其以有限通信增量换取更稳定的安全裕度。因此，优势主要表现为通信、安全和计算代价之间的折中，而非单纯追求最小通信量。”

求解时间只写“当前仿真规模下具有可接受的数值求解开销”。不要写成“证明满足真实机载实时控制要求”，除非确有飞控平台、通信协议、传感和嵌入式计算验证。

结论必须保留边界：

“上述结果仅适用于冻结参数、二维双积分器和当前随机场景范围。”

## 五、投稿前终检重点

投稿前按以下顺序查：

1. 数据未改变：种子、场景、统计口径、成功率、广播次数、RMSE、安全裕度、控制努力和求解时间不变。
2. 公式连续且变量解释完整。
3. 图题在图下，表题在表上，图表先引用后出现。
4. 表格为三线表，单位进表头，小数位统一。
5. 所有图件、图题、正文描述一致；不要让图题跨页或图片缺失。
6. 删除“ChatGPT Image”“生成图片”“待补充”等非论文痕迹。
7. 参考文献按首次出现顺序编号，文后文献均在正文出现。
8. 中英文摘要逐项对应，不新增摘要外数据。
9. 无批注、无修订痕迹、无隐藏模板文字。
10. 作者、单位、基金、通讯作者、参考文献真实性由作者最终确认。

若发现正文、表格和图片之间存在数值冲突，不得自行猜测。语言、术语、图题和版式不一致可以直接修正；数值冲突必须列为待确认项。

## 六、中稿概率评估口径

不要承诺“确定能发”。只能给目标期刊适配和风险分层。

评估时看：

- 目标期刊是否长期刊发相近仿真主题。
- 稿件是否明确是仿真研究，而非伪装实物实验。
- 是否有可复核模型、参数、场景、种子和评价指标。
- 是否有公平基线、失败记录和多场景统计。
- 创新是否克制且能被证据支撑。
- 参考文献是否真实、编号顺序是否正确。
- 版式、图表、摘要和结论是否进入目标期刊表达系统。

可用判断句：

“这不是保录判断。按当前证据链和目标期刊适配度，稿件属于中等偏高/中等/偏高风险，主要风险在于……；下一步应优先补强……。”

## 七、给用户的推进方式

面对基础弱、焦虑、想尽快毕业的用户，输出要短而可执行：

- 先给最可能实现的方向，不同时铺开 5 个大题。
- 每阶段只设一个主要目标和验收标准。
- 失败要记录，不要包装。
- 代码阶段先复现和诊断，少谈论文话术。
- 写作阶段先冻结数据，再统一术语、图表、公式和参考文献。
- 投稿概率分析要稳住情绪，但不能保证录用。
